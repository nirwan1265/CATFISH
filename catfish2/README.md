# catfish2 — CATFISH with Westfall–Young calibration

Self-contained working directory for the second CATFISH paper:
*Family-wise error control for correlated pathway tests in GWAS.*

```
catfish2/
  tex/        manuscript (catfish_wy.tex) + OUP class, bst, refs.bib
  tex/auto/   LaTeX tables and \newcommand numbers, generated by script 07
  scripts/    simulation, figure and table code
  results/    CSVs written by the scripts
  figures/    PNGs written by 05_figures.R
  data/       pathway sets, gene locations, pathway-name map
  logs/       run logs
```

## Run order

```bash
cd scripts
bash run_all.sh          # full run  (hours — see estimates below)
bash run_all.sh quick    # smoke test (minutes, NOT publication grade)
```

`run_all.sh` executes 01→04, then 05 (figures), then 07 (tables + numbers).
Then rebuild the manuscript:

```bash
cd ../tex
pdflatex catfish_wy && bibtex catfish_wy && pdflatex catfish_wy && pdflatex catfish_wy
```

## How numbers get into the manuscript

The Results section never hard-codes a simulation number. Each one is a LaTeX
macro (`\nTAnMax`, `\nLamMvnMin`, …) defined in `tex/auto/numbers_stub.tex` as a
red **[run 07]** placeholder and *redefined* by `tex/auto/numbers.tex`, which
`07_tables_and_numbers.R` regenerates from the result CSVs. The four
auto-generated tables work the same way: until they exist the manuscript shows a
red "Table pending" box and still compiles. Same for the five figures.

So: anything red in the PDF is a number the simulations have not produced yet.
Nothing in the Results is invented.

The real-data numbers (maize, human LDL) are **not** macros — they come from
analyses already run and are written in the text directly, with the generating
scripts noted in Methods §2.8.

## Known gap: 01 and 04 have no between-pathway overlap

`02` and `03` now build **one shared gene universe** (G = 3000 genes, LD blocks
of 50) and draw K = 150 pathways as overlapping subsets of the first 600 genes,
so each gene sits in several pathways and one draw moves all of them together.
That is the dependence Westfall–Young exists to control, and those two scripts
report the WY family-wise rate alongside the marginal type I error.

`02`, `03`, `08` and `09` all use the shared universe. `01` and `04` still draw
**each pathway independently**. In that design there is
no between-pathway dependence, so their WY thresholds are Bonferroni thresholds
with extra steps and the Bonferroni/WY ratio is ≈ 1 by construction. They are
still valid as marginal-calibration experiments; they just cannot speak to the
family-wise claim. Porting them to `make_universe` / `make_pathways` /
`components_array` is the next change.

## What is deliberately NOT here

**Simulated GWAS from genotypes.** No genotypes are simulated, no causal
variants assigned, no phenotypes generated, nothing pushed through the full
GWAS→MAGMA→CATFISH pipeline. The simulations operate on the omnibus statistic
and its null directly, with an exchangeable within-pathway correlation model.
This is stated plainly in Methods §2.7 and Limitations §5; the ranking results
are therefore statements about estimator behaviour, not power curves.

**A competitive-testing arm.** `magma_geneset_competitive` is not exported from
the CATFISH namespace, so the comparison against MAGMA's competitive test could
not be included. Given the saturation argument in Discussion §4.2 this is the
most important thing to add next.

**Sorghum under Westfall–Young.** The archived sorghum results do not include
the MAGMA `.genes.raw` file that the genome-wide correlated draw needs. Sorghum
appears in Table 5 (signal density) from its gene-level output only.

## Real-data inputs

Scripts 06 and the Westfall–Young runs read MAGMA output that lives outside this
repository (under `~/Documents/Research/results/MAGMA/MAGCAT`). Every path in
`06_maize_candidate_genes.R` can be overridden with an environment variable —
see the header of that file.

## Dependencies

R ≥ 4.0 with `stats`, `utils`, `data.table`; optionally `evir` for the
generalized-Pareto tail extrapolation. The LaTeX build needs the OUP class
(bundled in `tex/`) plus `algorithm`/`algorithmicx` (also bundled, since the OUP
class requires them and they are missing from some TeX Live installations).
